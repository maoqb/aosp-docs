# 错误处理与调试工具

Native 层需要区分可恢复失败、编程错误和内存安全错误。Android 代码常用状态码或 Result 返回可恢复失败，而不是依赖 C++ 异常。

## 错误模型

状态码适合底层 API：调用方必须检查并决定重试、降级或上报。`errno` 只在失败后立即读取，后续系统调用可能覆盖它。断言适合违反内部不变量的编程错误，不能替代外部输入校验。

异常在很多 Android Native 路径中较少使用，因为跨 ABI、性能关键路径和 C 接口的异常边界复杂。阅读接口时先找返回值约定，再看日志是否只是诊断而非错误传递。

## Sanitizer

AddressSanitizer 擅长定位越界、use-after-free、double free；UndefinedBehaviorSanitizer 检查有符号溢出、错误转换等未定义行为；ThreadSanitizer 用于数据竞争。报告的第一处非法访问通常比最后崩溃点更接近根因。

## Native 崩溃阅读

先确认 signal、fault address 和崩溃线程；再用未裁剪符号定位栈；最后追踪对象所有权和并发访问。空指针崩溃不一定是“缺少空判断”，也可能是上游生命周期或初始化顺序错误。

## Android 阅读视角

熟悉 `logcat`、tombstone、`addr2line`、`ndk-stack` 与 AOSP 的日志宏。修改系统服务时，日志应包含操作、对象身份和失败码，但不要把敏感数据或高频循环日志写入生产路径。

## 易错点

- 错误日志不等于已处理错误；必须检查控制流是否真的返回失败。
- 不要吞掉错误后继续使用未初始化对象。
- 修复 use-after-free 时优先修正所有权，而非仅在访问前加 null 检查。
