# 智能指针与所有权

智能指针把“谁负责销毁对象”写进类型。读 Native 代码时，所有权往往比业务逻辑更先决定正确性。

## unique_ptr

`std::unique_ptr<T>` 表示唯一所有者，不能复制，只能移动；适合工厂返回值、独占成员和 C 资源封装。优先使用 `std::make_unique`：

```cpp
auto connection = std::make_unique<Connection>();
```

## shared_ptr 与 weak_ptr

`shared_ptr` 适合多个平等所有者，强引用归零时销毁对象，但它会隐藏生命周期、产生计数开销，也可能形成环。`weak_ptr` 不延长生命周期，使用 `lock()` 成功后才能安全访问对象，是打破循环引用的标准方式。

## 拥有与借用

拥有者可短暂传递 `T*` 或 `T&`；接收方不得 delete 或长期保存，除非接口约定如此。绝不能从同一个裸指针构造多个 `shared_ptr`，否则不同控制块会重复销毁同一对象。

## Android 阅读视角

标准智能指针与 `android::sp/wp` 不可混为一谈：后者基于 `RefBase`，拥有不同的生命周期钩子。回调捕获强引用会延长服务、线程或 Activity 对应 Native 对象的寿命，必须检查是否需要弱引用。

## 易错点

- `shared_ptr` 不保证目标对象线程安全，只保证控制块计数安全。
- `weak_ptr` 提升失败是正常业务分支，不是异常。
- 裸指针并非总是坏；明确的短期非拥有参数非常合适。
