# 指针、引用与 const

Native 接口的指针和引用同时表达可空性、可修改性与借用关系。读函数签名时，应先判断对象是否必须存在、谁保证生命周期、调用能否修改它。

## 指针与引用

`T*` 可为 `nullptr`、可改变指向，适合可选参数或非拥有借用；`T&` 必须绑定有效对象、不能重新绑定，适合必需的借用：

```cpp
void SetName(std::string* name);         // 可空，且可修改目标
void PrintName(const std::string& name); // 必须存在，只读借用
```

两者都不自动表达所有权。若被调用方保存借用供以后使用，接口必须明确它的存活条件，或改用拥有类型。

## const 的位置

`const T*` 表示不能经该指针修改对象；`T* const` 表示指针自身不能改指向；`const T&` 是只读引用。成员函数末尾的 `const` 表示不修改对象可观察状态。const 是接口契约和编译期保护，但不保证线程安全。

## 空值与边界

检查裸指针空值是契约的一部分。C++ 数组退化为指针后会丢失长度，优先用 `std::span`、`std::vector` 或显式长度参数。不要返回局部 `string.c_str()`；字符串析构后指针立即失效。

## Android 阅读视角

`sp<T>` 多表示强持有，`T*` 和 `T&` 多表示借用，但最终仍要结合成员、回调时机和线程模型确认。同步调用里的裸指针可能安全；异步 lambda 捕获的引用可能在执行前失效。

## 易错点

- C++ 引用不是 Java 引用类型：它不能为 null，也不是可重新赋值的句柄。
- 不用 `const_cast` 绕开设计；修改原本为 const 的对象会导致未定义行为。
