# 引用：给已有对象起别名

引用不是一个“更安全的指针”，而是已有对象的别名。它适合表达“参数必须存在，但函数不负责销毁它”；如果对象可能不存在，指针或 `std::optional` 往往更清楚。

## 1. 引用必须绑定对象

```cpp
int value = 10;
int& alias = value;
alias += 5;                 // 修改的就是 value
const int& readonly = value; // 只能通过 readonly 读取
```

普通左值引用 `T&` 初始化后不能改绑到另一个对象，也没有合法的“空引用”状态。`alias = other` 是把 `other` 的值赋给原对象，不是让 `alias` 改指向。

## 2. 三种参数表达三种意图

```cpp
void inspect(const std::string& text); // 只读借用
void normalize(std::string& text);     // 可写借用
void save(std::string text);           // 取得一份自己的值
```

- `const T&`：不复制，函数承诺不通过该引用修改对象。
- `T&`：调用者会看到修改，适合作为明确的输入输出参数。
- `T`：函数拥有独立参数；调用者可复制传入，也可用 `std::move` 转移。

小型标量如 `int`、`bool` 通常直接按值传递更简单。不要为了“看起来高效”把所有参数都改成引用。

## 3. const 引用能延长临时对象，但不能拯救悬空对象

```cpp
const std::string& text = std::string("temporary");
// 临时 string 的寿命延长到 text 离开作用域
```

这种延长只适用于特定的直接绑定。下面仍然错误：

```cpp
const std::string& bad() {
    std::string local = "gone";
    return local; // 返回后 local 已销毁，引用悬空
}
```

**悬空引用（dangling reference）**是目标已经销毁、引用却还被使用。引用语法不保存对象寿命，跨线程、异步回调和容器扩容后尤其要重新检查目标是否仍存在。

## 4. 完整示例：用引用表达只读和可写借用

```cpp title="reference_demo.cpp"
#include <algorithm>
#include <cctype>
#include <iostream>
#include <string>

void trimLeft(std::string& text) {
    auto first = std::find_if(text.begin(), text.end(), [](unsigned char ch) {
        return !std::isspace(ch);
    });
    text.erase(text.begin(), first);
}

void printLength(const std::string& text) {
    std::cout << text << " length=" << text.size() << '\n';
}

int main() {
    std::string name = "   SurfaceFlinger";
    trimLeft(name);
    printLength(name);
}
```

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic reference_demo.cpp -o reference_demo
./reference_demo
```

输出为 `SurfaceFlinger length=14`。`trimLeft` 明确修改调用者对象，`printLength` 只借用它；两者都不拥有 `name`。

## 5. 读接口时先问三个问题

看到引用参数，依次确认：目标是否可能为空、函数是否保存该引用、保存后的目标由谁保证存活。`const T&` 只限制通过当前引用修改，不等于线程安全，也不等于被引用对象永远不变。

规则细节可查 C++17 工作草案 N4659 的 §11.3.2 `[dcl.ref]` 与 §15.2 `[class.temporary]`。
