# 线程、锁与原子变量

并发代码的核心是共享状态、可见性和执行顺序。先画出哪些字段被多个线程读写，再选择 mutex、条件变量或原子变量。

## mutex 与 RAII

mutex 保护一组需要保持一致的状态。使用 `std::lock_guard` 限定固定加锁范围，使用 `std::unique_lock` 支持条件变量等待和提前解锁。锁应保护数据而非“函数”；同一字段必须始终由同一规则保护。

## 条件变量

条件变量不是事件队列，可能虚假唤醒，因此等待必须带谓词：

```cpp
condition_.wait(lock, [this] { return stopped_ || !queue_.empty(); });
```

修改谓词状态时通常先持锁，再 notify。退出路径要唤醒所有等待者并让它们看到终止状态。

## 原子变量与内存序

原子变量适合简单 flag、计数器或无锁协议；它不自动保护关联的复杂对象。默认顺序一致性最易正确，只有在已理解 happens-before 关系时再使用 acquire/release 或 relaxed 优化。

## Android 阅读视角

系统服务常同时有 Binder 线程、Looper 线程、合成线程和回调线程。阅读前确定线程归属；看到 `FooLocked`、`mLock` 或 `Mutex::Autolock` 时建立锁顺序表。不要持锁做 Binder 调用或回调，防止跨服务反向等待。

## 易错点

- `volatile` 不是线程同步工具。
- 引用计数线程安全不代表对象内部字段线程安全。
- 先检查再使用若未在同一锁/原子协议内，仍然是竞态。
