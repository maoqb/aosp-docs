# 拷贝、移动与值语义

C++ 的传参、返回值和容器操作可能复制对象，也可能转移资源。理解这两种语义，才能正确阅读 buffer、fd 和任务队列相关代码。

## 拷贝与移动

拷贝构造/赋值让两个对象各自拥有等价状态；移动构造/赋值把资源控制权交给新对象。移动后的对象仍须可析构和可重新赋值，但不能再假定它保留原值。

```cpp
std::vector<std::string> names;
std::string name = LoadName();
names.push_back(std::move(name));
```

`std::move` 本身不移动资源，只把表达式转换成右值，允许目标函数选择移动构造。对之后还需读取的对象调用它是错误信号。

## 特殊成员函数

编译器可生成默认构造、析构、拷贝和移动操作。类只含值语义成员时遵循 Rule of Zero，避免手写这些函数；直接管理独占资源时，删除拷贝、实现移动，或用成熟 RAII 成员取代手工资源管理。

## 返回值与性能

现代 C++ 对 `return object;` 常执行 RVO/NRVO，直接返回局部对象即可。不要为了“优化”写 `return std::move(object);`，它可能妨碍返回值消除。

## Android 阅读视角

看到 `std::move` 时，追踪资源从何处交给何处、源对象随后是否还被访问。删除 copy constructor 通常意味着类型包含锁、fd、Binder 连接或身份状态，不能复制。跨线程队列常通过移动转交任务，避免大对象复制。

## 易错点

- 移动不是浅拷贝；实现必须维持资源唯一性和类不变量。
- const 对象通常不能有效移动，因为移动会改变源对象。
- `sp<>` 移动的是引用句柄，不是远端 Binder 对象本身。
