# 拷贝、移动与值语义

Java 中把一个对象变量赋给另一个变量，多数时候是在复制引用。C++ 中 `Frame second = first;` 通常是在构造第二个 Frame。第二个对象能否独立修改、资源是否共享、原对象还能不能用，取决于类型定义的拷贝和移动语义。

本篇将“表达式类别”“重载选择”“资源转移”分开解释，示例均使用 C++17。

## 1. 先问类型希望表达什么

值语义表示对象像独立的值一样使用。例如拷贝一个 string 后，修改副本通常不改变原字符串。句柄语义则表示多个对象可能访问同一底层实体，例如 shared_ptr 的拷贝会共同持有同一目标。

一个 fd 所有者不能简单地按成员字节复制，因为那会产生两个负责关闭同一 fd 的对象。因此编写类之前，应明确它属于独立值、独占句柄还是共享句柄。

“有一个拷贝构造函数”不意味着它做深拷贝。深浅关系由实现决定。编译器生成的拷贝通常逐成员拷贝；成员如果是裸指针，只会复制地址。

## 2. 构造和赋值的区别

```cpp
Frame second = first;
second = third;
```

第一行在 second 尚不存在时初始化它，涉及拷贝构造；第二行修改已经存在的 second，涉及拷贝赋值。构造只需建立新状态，赋值还需正确处理目标已有资源。

相应地，特殊成员函数常见形状是：

```cpp
Frame(const Frame& other);
Frame& operator=(const Frame& other);
Frame(Frame&& other) noexcept;
Frame& operator=(Frame&& other) noexcept;
```

这些是声明片段。返回 Frame& 让赋值表达式可继续使用；noexcept 表达异常承诺，后文会解释它为何影响容器行为。

## 3. 左值、纯右值和将亡值

值类别属于表达式，不是对象的永久标签。

| 表达式 | 常见类别 | 阅读含义 |
| --- | --- | --- |
| 有名字的变量 `frame` | 左值 lvalue | 指向一个可定位对象 |
| `Frame{}` | 纯右值 prvalue | 用于生成值，C++17 有直接构造规则 |
| `std::move(frame)` | 将亡值 xvalue | 允许资源被转移的视图 |
| 已命名的 `Frame&& argument` 的名字 | 左值 lvalue | 名字表达式仍是左值 |

不能仅凭“临时”或“以后不用了”凭感觉判断重载。编译器依据表达式类别和类型进行匹配。

## 4. std::move 为什么没有移动代码

完整程序 move_category.cpp：

```cpp title="move_category.cpp"
#include <iostream>
#include <string>
#include <utility>

void inspect(const std::string&) {
    std::cout << "const reference\n";
}

void inspect(std::string&&) {
    std::cout << "rvalue reference\n";
}

void relay(std::string&& value) {
    inspect(value);
    inspect(std::move(value));
}

int main() {
    std::string text = "frame";
    inspect(text);
    inspect(std::move(text));
    relay(std::string("temporary"));
}
```

编译运行：

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic move_category.cpp -o move_category
./move_category
```

输出：

```text
const reference
rvalue reference
const reference
rvalue reference
```

两个 inspect 都没有保存或修改参数。因此 std::move(text) 只让调用匹配右值引用重载，并没有移动 string 内部资源。

relay 的参数类型虽然是右值引用，但函数体里的 value 是一个有名字的表达式，所以第一次匹配 const 引用；显式 std::move 后才选择右值引用重载。

真正的移动发生在目标构造函数、赋值运算符或其他业务函数的实现中。

## 5. 完整示例：复制与转移资源

```cpp title="packet_move.cpp"
#include <iostream>
#include <string>
#include <utility>

class Packet {
public:
    explicit Packet(std::string payload)
        : payload_(std::move(payload)) {}

    Packet(const Packet& other)
        : payload_(other.payload_) {
        std::cout << "copy\n";
    }

    Packet(Packet&& other) noexcept
        : payload_(std::move(other.payload_)) {
        std::cout << "move\n";
    }

    Packet& operator=(const Packet&) = default;
    Packet& operator=(Packet&&) noexcept = default;

    void replace(std::string payload) {
        payload_ = std::move(payload);
    }

    const std::string& payload() const {
        return payload_;
    }

private:
    std::string payload_;
};

int main() {
    Packet original("frame");
    Packet copied(original);
    Packet moved(std::move(original));

    copied.replace("copy-only");
    original.replace("reused");

    std::cout << copied.payload() << '\n';
    std::cout << moved.payload() << '\n';
    std::cout << original.payload() << '\n';
}
```

输出：

```text
copy
move
copy-only
frame
reused
```

copied 拥有自己的字符串值；moved 从 original 的 string 成员接收资源。我们没有在移动后假设 original 必为空，而是先给它赋新值再使用。

标准库许多移动后对象处于有效但未指定状态，可析构、可进行满足前置条件的操作。unique_ptr 的移动后为空有更具体保证。用户自定义类型不会仅因写了 std::move 就自动获得正确的移动后不变量，必须由实现确保。

示例用日志展示调用位置；实际资源类应谨慎处理日志潜在失败，不要把会抛出的任意操作塞进 noexcept 移动函数。

## 6. Rule of Zero、Five 和隐式生成

若成员已经正确管理资源，例如 string、vector、unique_ptr，外层类通常可以不写析构、拷贝和移动，由编译器按成员语义生成。这就是 Rule of Zero 的实际价值。

一旦直接管理裸资源，就必须整体考虑析构、拷贝构造、拷贝赋值、移动构造、移动赋值，不能只补一个析构。否则默认逐成员拷贝很容易导致 double free。

还有一个常见陷阱：用户声明析构函数，包括 `~Frame() = default;`，会影响隐式移动操作的生成。一个看似无害的改动，可能使容器转而复制对象。若确需该析构，应明确审查复制和移动是否要 default 或 delete。

不要盲目给所有函数写 default；含有 mutex 的类无法像普通值那样默认复制，含有独占资源的类也未必允许拷贝。

## 7. 为什么移动常标 noexcept

vector 扩容通常要将旧元素搬到新存储。如果某个元素移动到一半抛异常，恢复原状态可能困难；当复制可用而移动可能抛出时，实现常选择复制以维持异常保证。

因此一个资源句柄若能通过几个指针或整数交换完成移动，准确标为 noexcept 可以帮助容器选到安全且高效的路径。它不是随意的性能开关：一旦函数内异常逃出，程序会 terminate。

## 8. 返回值消除比“手工移动”更基础

C++17 中：

```cpp
Packet makePacket() {
    return Packet("frame");
}
```

同类型纯右值返回可以直接构造结果，不需要先有一个临时对象再移动。这与返回一个命名局部变量时可能发生的 NRVO 不完全一样；NRVO 仍有适用条件，并非所有场景强制发生。

对普通局部对象优先 `return result;`，让返回值消除或隐式移动规则工作。`return std::move(result);` 常常失去 NRVO 机会。不能看到没有显式 move 就断言一定深拷贝。

## 9. const 为什么可能让移动变成复制

若 source 是 `const Packet`，std::move(source) 得到 const Packet&&。普通移动构造接受 Packet&&，因为转移资源通常要修改源；它不能绑定 const 源。

如果拷贝构造接受 const Packet&，它反而可匹配，于是代码能编译却执行复制。只有移动没有复制的类型则可能编译失败。分析性能时要查看 const 和选中的重载，而不是数 move 出现次数。

## 10. Android 阅读中的三种 move

| 源类型 | 常见转移内容 | 不应误解为 |
| --- | --- | --- |
| unique_fd | 关闭 fd 的责任 | 内核文件内容被复制 |
| vector/大块存储所有者 | 底层存储管理权 | 每个字节必然搬运 |
| sp/shared_ptr | 一个强引用句柄 | 远端 Binder 对象移动到本进程 |

看到任务入队、事务合并或 buffer 所有者移交，先标出转移前后的拥有者，再检查源对象剩余用途。若一个函数“消费”参数，按值接收 move-only 类型往往能直接表达这份契约。
