# 线程池：固定工人反复处理任务

线程池避免为每个短任务反复创建线程。它通常由任务队列、若干工作线程、条件变量和关闭协议组成；难点不是启动线程，而是停止接单、处理剩余任务并安全 `join`。

## 1. 最小状态模型

```text
post 任务 → 入队 → notify_one → worker 取出 → 锁外执行
关闭     → stopping=true → notify_all → 队列排空 → worker 退出 → join
```

任务必须在锁外执行，否则一个慢任务会阻止生产者入队，也可能在任务递归投递时死锁。

## 2. 完整示例

```cpp title="thread_pool_demo.cpp"
#include <atomic>
#include <condition_variable>
#include <functional>
#include <iostream>
#include <mutex>
#include <queue>
#include <stdexcept>
#include <thread>
#include <utility>
#include <vector>

class ThreadPool {
public:
    explicit ThreadPool(std::size_t count) {
        for (std::size_t i = 0; i < count; ++i) {
            workers_.emplace_back([this] { workerLoop(); });
        }
    }

    ~ThreadPool() {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            stopping_ = true;
        }
        ready_.notify_all();
        for (std::thread& worker : workers_) worker.join();
    }

    void post(std::function<void()> task) {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            if (stopping_) throw std::runtime_error("pool is stopping");
            tasks_.push(std::move(task));
        }
        ready_.notify_one();
    }

private:
    void workerLoop() {
        for (;;) {
            std::function<void()> task;
            {
                std::unique_lock<std::mutex> lock(mutex_);
                ready_.wait(lock, [this] { return stopping_ || !tasks_.empty(); });
                if (stopping_ && tasks_.empty()) return;
                task = std::move(tasks_.front());
                tasks_.pop();
            }
            task();
        }
    }

    std::mutex mutex_;
    std::condition_variable ready_;
    std::queue<std::function<void()>> tasks_;
    std::vector<std::thread> workers_;
    bool stopping_ = false;
};

int main() {
    std::atomic<int> sum{0};
    {
        ThreadPool pool(3);
        for (int value = 1; value <= 100; ++value) {
            pool.post([&sum, value] { sum.fetch_add(value); });
        }
    } // 析构等待队列排空并 join
    std::cout << sum.load() << '\n';
}
```

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -pthread thread_pool_demo.cpp -o thread_pool_demo
./thread_pool_demo
```

输出 `5050`。析构设置停止标记后不再接收新任务，但 worker 只有在“正在停止且队列为空”时退出，因此已接收任务不会被静默丢弃。

## 3. 真实线程池还要明确的契约

- 队列是否有容量上限，满时阻塞、失败还是丢任务。
- 任务抛异常时由谁捕获，是否通过 `future` 返回。
- 关闭是排空队列还是立即取消，能否从 worker 内触发关闭。
- 任务捕获对象如何保活，是否允许任务晚于提交者执行。
- 线程数如何选；CPU 密集与阻塞 I/O 的策略不同。
- 谁负责保证析构开始后不再调用 `post`；成员函数与对象析构并发本身不是安全用法。

这个示例用于解释协议，不是通用生产线程池。生产代码还应处理构造部分失败、任务异常和自 `join` 等边界。
