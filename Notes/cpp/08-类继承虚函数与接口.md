# 类、继承、虚函数与接口

Android Native 的 Binder 接口、HAL 和 listener 回调都依赖多态。阅读继承体系时，需区分静态类型、动态类型和对象销毁责任。

## 虚函数分派

基类指针或引用调用 virtual 方法时，运行时按真实对象类型分派：

```cpp
class Renderer { public: virtual void Draw() = 0; virtual ~Renderer() = default; };
class GpuRenderer final : public Renderer { public: void Draw() override; };
```

纯虚函数定义抽象接口；`override` 让编译器检查签名；`final` 表达不可继续派生或重写的约束。

## 构造、析构与多态

多态基类必须有 virtual 析构函数，否则通过基类指针销毁派生对象会遗漏派生析构。构造和析构期间的虚函数不会分派到尚未构造或已析构的派生部分，因此关键初始化不能依赖这类回调。

## 组合优先

继承适合清晰的 is-a 接口关系；复用实现通常优先组合。深继承树会使状态、锁和生命周期难以追踪。小而稳定的接口配合组合依赖，更接近 Android 服务代码的可维护方式。

## Android 阅读视角

遇到 `override` 时先读基类契约，再找所有实现；遇到基类 `sp<>` 时确认实际对象由谁构造和持有。Binder 的 `Bp*`/`Bn*` 是典型多态，但 Proxy 与 Stub 承担的是不同进程侧职责。

## 易错点

- C++ 方法并非默认动态分派，只有 virtual 才有多态。
- 按值把派生对象赋给基类对象会发生对象切片。
- 带状态的多重继承风险很高；接口型多继承相对可控。
