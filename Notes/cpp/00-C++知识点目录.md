<h2 style="text-align: start;"><strong>2.3 在 VS Code 里启用</strong></h2>

1. 用“文件 → 打开文件夹”打开 `~/code/android-16.0.0_r4`，使根目录下的 `.vscode` 设置生效。
2. 打开 `binderAddInts.cpp`。
3. 按 `Ctrl+Shift+P`，执行 `clangd: Restart language server`。如果扩展没有重新启动，执行 `Developer: Reload Window` 后再打开 C++ 文件。
4. 在“输出”面板选择 clangd 的输出通道，确认进程启动并加载编译数据库。

<p style="text-align: start;">常用操作：</p>

| 操作 | 默认快捷键 / 菜单 |
| --- | --- |
| 转到定义 | F12 |
| 预览定义 | Alt+F12 |
| 转到实现 | Ctrl+F12，或右键“转到实现” |
| 查找引用 | Shift+F12 |
| 手动触发补全 | Ctrl+Space |
| 查看类型、参数说明 | 鼠标悬停 |

<p style="text-align: start;">例如，<code>binder</code> 的静态类型是 <code>sp&lt;IBinder&gt;</code>，对 <code>binder-&gt;transact()</code> 执行“转到定义”可能定位到接口声明。要看 <code>BBinder</code>、<code>BpBinder</code> 等派生类的实现，使用“转到实现”；实际运行会调用哪一个实现，还要结合对象的动态类型和调用链判断。</p>

<p style="text-align: start;">全量编译数据库约 1.1 GB，首次全库后台索引需要时间。打开文件的语法解析和全库索引是不同的工作，跨文件引用结果会随着后台索引逐步完善。</p>

<p style="text-align: start;">按 <code>Ctrl+Shift+B</code> 执行默认任务：</p>

<h2 style="text-align: start;"><strong>2.5 新建自己的 Native 程序</strong></h2>

<p style="text-align: start;">可以在 AOSP 树中建立自己的模块目录，例如 <code>system/extras/binder_demo/</code>，放入 <code>main.cpp</code> 和 <code>Android.bp</code>。下面是声明普通可执行程序及 Binder 依赖的示例：</p>

```bp
cc_binary {
    name: "binder_demo",
    srcs: ["main.cpp"],
    shared_libs: [
        "libbinder",
        "libutils",
        "liblog",
    ],
}
```

<p style="text-align: start;">源文件可以根据实际使用的类包含头文件：</p>

```cpp
#include <binder/Binder.h>
#include <binder/Parcel.h>
#include <binder/ProcessState.h>
#include <binder/IPCThreadState.h>
```

<p style="text-align: start;">上面的片段展示模块配置和头文件用法，具体业务与 <code>main()</code> 由程序实现。性能测试程序可以像 <code>binderAddInts</code> 一样使用 <code>cc_benchmark</code>。</p>

<p style="text-align: start;">准备好源文件后，在主机终端运行：</p>

```bash
cd ~/code/android-16.0.0_r4
source build/envsetup.sh
lunch sdk_phone64_x86_64-trunk_staging-eng
export SOONG_GEN_COMPDB=1
export SOONG_LINK_COMPDB_TO="$PWD"
m -j4 binder_demo
```

<p style="text-align: start;">这会构建模块及其必要依赖，并启用编译数据库生成。编译后让 clangd 重新加载数据库，新源文件就能使用自己的编译参数。新模块的 VS Code 构建和部署任务，需要把示例任务中的模块名及产物路径同步改为新模块。</p>

<p style="text-align: start;">只更新编译数据库时可以执行：</p>

```bash
m -j4 nothing
```

<p style="text-align: start;"><code>m nothing</code> 不负责把所有生成头文件编出来。如果 clangd 报缺少 AIDL 等生成头文件，应先构建对应模块。Soong 的生成说明见 <a target="_blank" rel="noopener noreferrer nofollow" href="http://compdb.md">compdb.md</a>。</p>

<h2 style="text-align: start;"><strong>7. 当前验证结果与范围</strong></h2>

<p style="text-align: start;">已使用与编辑器相同的语言服务协议验证：</p>

- `binderAddInts.cpp`、`ProcessState.cpp`、`IPCThreadState.cpp`、`BpBinder.cpp`、`Binder.cpp`、`Parcel.cpp` 均无解析错误。
- `startThreadPool()` 的定义查询定位到 `ProcessState.cpp`。
- `writeInt32()` 的定义查询定位到 `Parcel.cpp`。
- `transact()` 的实现查询返回 `BBinder` 和 `BpBinder` 对应实现。
- 在内存中的编辑缓冲区输入 `send.wri`，补全结果包含 `writeInt32`、`writeInt32Array` 和 `writeInt32Vector`；磁盘源码未因该补全检查改变。
- 实际执行了 VS Code 构建任务和部署运行任务中的命令，程序返回 `0 + 3 = 3`。

<p style="text-align: start;">导航验证时相关 <code>.cpp</code> 已打开，证明编译参数、解析和这些语言服务请求可用。VS Code 界面仍需加载工作区设置并启动 clangd，其他未打开文件的全库导航依赖后台索引。</p>
