# 对象生命周期与初始化

C++ 对象的构造和析构通常是确定的：局部对象离开作用域立刻析构，而不是等待 GC。这既让资源管理可靠，也要求你严格避免保存已销毁对象的地址。

## 存储期

局部对象拥有自动存储期；`static` 对象通常活到进程退出；动态对象由 `new` 创建，必须由明确拥有者负责销毁。优先写局部对象：

```cpp
void Read() {
  std::string name = "surface"; // 函数结束时析构
}
```

不能返回局部对象的指针或引用。地址表面上仍存在，但对象已经不再存活，任何访问都是未定义行为。

## 初始化列表与顺序

成员在构造函数体执行前初始化，且严格按**成员声明顺序**初始化。`const` 成员、引用成员和无默认构造函数的成员必须在初始化列表中初始化：

```cpp
class Session {
 public:
  Session(int id, std::string name) : id_(id), name_(std::move(name)) {}
 private:
  int id_;
  std::string name_;
};
```

这避免先默认构造再赋值。基类先于派生类构造，析构顺序相反；成员也按声明顺序的反向析构。

## 临时对象

临时对象通常在完整表达式结束时销毁。`const T&` 绑定临时对象只会在该引用的局部作用域内延长生命周期；把这个引用存入成员、返回引用或交给异步回调并不会延长，极易产生悬空引用。

## Android 阅读视角

读一个服务类时，先看构造函数建立哪些不变量、析构函数释放哪些资源。构造对象不一定意味着服务已启动：线程、Binder 注册或依赖连接常在 `init`、`start` 等方法中完成。

## 易错点

- `new` 不等于“更像 Java 对象”；大部分对象应放栈上或由智能指针持有。
- 析构期间的虚调用不会分派到已经析构的派生部分。
- 基础类型成员若未初始化，读取它就是未定义行为。
