# 编译、链接与头文件

C++ 源码要经历预处理、编译、汇编和链接。每个 `.cpp` 连同它展开的头文件构成一个**编译单元**；编译器独立处理它，链接器把目标文件和库组合为可执行文件或 `.so`。

## 声明、定义与符号

声明告诉编译器“这个名字存在、类型是什么”，定义提供实体或函数体。函数声明可放头文件，非 `inline` 函数定义只能在整个程序中出现一次：

```cpp
// calculator.h
int Add(int left, int right);
// calculator.cpp
int Add(int left, int right) { return left + right; }
```

调用方只 include 头文件时能通过编译；若 `calculator.cpp` 未参与最终链接，会报 `undefined reference`。反之，将普通函数定义放进被多个 `.cpp` include 的头文件，常会报重复定义。

## 头文件设计

头文件放稳定接口：类型声明、函数声明、模板定义、常量和必要的 inline 函数；实现细节留在 `.cpp`。使用 `#pragma once` 或 include guard 防止同一文件重复展开。仅保存 `Foo*`、`Foo&` 或智能指针时可前置声明 `class Foo;`，只有需要对象大小、成员或继承关系时才 include 完整定义。

## Android.bp 阅读方法

`srcs` 指定编译源码，`shared_libs`/`static_libs` 指定链接库，`header_libs` 只提供头文件可见性。排查符号问题依次检查：声明是否 include、实现是否在 `srcs`、实现库是否被链接、命名空间与签名是否一致。能 include 头文件不代表已经链接实现。

## 易错点

- `#include` 是预处理期文本展开，不是运行时导入。
- 文件作用域 `static` 限制符号只在当前编译单元可见；它不是静态库。
- 模板定义通常必须放头文件，因为实例化发生在使用它的编译单元。
- 改头文件会触发大量重编译，减少不必要 include 能显著改善构建速度。
