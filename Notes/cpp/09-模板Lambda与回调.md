# 模板、Lambda 与回调

模板让算法和类型在编译期组合，Lambda 则把可执行逻辑作为值传递。Android Native 中常用它们实现容器算法、任务队列和 listener 回调。

## 读模板的正确顺序

不要先展开所有模板细节。先在调用点确定实参类型，再回到模板定义看它对类型要求什么：是否可复制、是否有某个成员函数、返回类型如何推导。`auto`、`decltype` 和类型别名常用于降低模板表达式复杂度。

模板定义通常放头文件，因为编译器必须在使用点看到完整定义以生成实例。错误信息很长时，优先找第一条涉及你调用点的类型不匹配，而不是阅读全部实例化栈。

## Lambda 捕获

```cpp
auto by_value = [name] { Use(name); }; // 复制 name
auto by_ref = [&name] { Use(name); };  // 借用 name
auto member = [this] { Use(field_); }; // 借用当前对象
```

异步执行时，引用捕获和 `[this]` 最危险：任务真正运行时，被借用对象可能已析构。需要延长对象寿命时捕获 `shared_ptr`/`sp<>`；需要避免延长时捕获 `weak_ptr`/`wp<>` 并在执行时提升。

## 回调类型

函数指针无状态、开销低；模板参数通常可避免类型擦除；`std::function` 可统一容纳不同可调用对象，但可能产生分配和间接调用。接口回调还要明确在哪个线程调用、是否允许重入、回调期间对象是否存活。

## Android 阅读视角

读 `post`、`schedule`、`addListener` 一类 API 时，先追踪回调最终在哪个 Looper/线程执行。检查 lambda 捕获列表比检查函数体更早发现生命周期和死锁问题。

## 易错点

- `[=]` 会隐式捕获 this（具体规则随语言版本演进），关键代码建议显式捕获。
- 不要把引用捕获的局部变量交给延迟任务。
- `std::function` 为空时调用会抛 `bad_function_call`，调用前需保证已设置。
