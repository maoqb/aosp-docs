# 进程：独立地址空间、继承的 fd 和退出状态

进程是操作系统隔离资源和地址空间的基本单位。线程共享同一进程的大部分内存，而两个进程不能靠普通指针访问对方对象；它们需要 pipe、Unix Socket、共享内存等 IPC 机制。

## 1. fork 后有父子两条执行流

```cpp
pid_t pid = fork();
if (pid == 0) {
    // 子进程
} else if (pid > 0) {
    // 父进程，pid 是子进程号
} else {
    // 创建失败
}
```

`fork()` 返回后，父子进程看到相似的虚拟地址内容，但不是可以无锁共享的同一批普通变量。现代系统通常使用写时复制优化，任一方修改普通内存不会自动同步给另一方。

## 2. exec 替换当前程序

`exec` 家族成功后不会返回：当前进程号保留，但地址空间和正在执行的程序被新程序替换。常见启动模型是父进程 `fork`，子进程整理 fd 后 `exec`，父进程用 `waitpid` 回收退出状态。

文件描述符默认会被子进程继承。无需跨 `exec` 保留的 fd 应在创建时使用 `O_CLOEXEC`、`SOCK_CLOEXEC` 等原子标志，避免多线程窗口中的泄漏。

## 3. 完整示例：父子进程通过 pipe 传值

```cpp title="process_demo.cpp"
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

#include <cstdlib>
#include <iostream>

int main() {
    int channel[2];
    if (pipe(channel) == -1) return 1;

    const pid_t pid = fork();
    if (pid == -1) return 1;

    if (pid == 0) {
        close(channel[0]);
        const int answer = 42;
        const bool ok = write(channel[1], &answer, sizeof(answer)) == sizeof(answer);
        close(channel[1]);
        _exit(ok ? 0 : 2);
    }

    close(channel[1]);
    int answer = 0;
    const ssize_t bytes = read(channel[0], &answer, sizeof(answer));
    close(channel[0]);

    int status = 0;
    if (waitpid(pid, &status, 0) == -1) return 1;

    if (bytes == sizeof(answer) && WIFEXITED(status)) {
        std::cout << "child=" << answer
                  << " exit=" << WEXITSTATUS(status) << '\n';
    }
}
```

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic process_demo.cpp -o process_demo
./process_demo
```

输出 `child=42 exit=0`。父子分别关闭不用的 pipe 端，父进程读取并 `waitpid`，子进程使用 `_exit` 避免再次刷新从父进程复制来的用户态缓冲。

## 4. 多线程程序 fork 的额外限制

多线程进程 `fork` 后，子进程只保留调用 `fork` 的线程，其他线程持有的用户态锁可能永远无人释放。在 `fork` 与 `exec` 之间只能调用相应平台允许的操作；复杂逻辑应放到新程序启动后。POSIX 规则见 [fork](https://pubs.opengroup.org/onlinepubs/9799919799/functions/fork.html)、[exec](https://pubs.opengroup.org/onlinepubs/9799919799/functions/exec.html) 与 `waitpid` 规范。
